# Information Density

目标：避免“只有标题 + 菜图”的平淡，也避免变成促销传单。

## Default Campaign Stack

在用户满足“主标题 + 副标题 + N”后，默认尝试组织：

1. 主标题
2. 副标题
3. 1 条 Slogan / 传播句
4. 3–4 个卖点
5. 店名 / 品牌名（若有）
6. 地址（若有）
7. 电话 / 预订电话（若有）
8. QR 区域（真实二维码优先；否则预留 safe zone）
9. 极少量装饰文字 / 编号 / 地域标签

## Slogan Rule

如果用户没有提供 Slogan，可以生成原创“传播微文案”，但不得冒充官方 Slogan。

建议 4–14 个汉字，服务主标题，不重复副标题。

## Selling Point Rule

默认 3–4 个，每个 2–6 个汉字或极短短语。

优先来源：

- 用户明确提供的核心食材 / 卖点
- 菜名可直接支持的风味
- 图片可见且明确的感官特征

可以写：

- 鲜麻开胃
- 鱼片嫩滑
- 酸菜提鲜
- 热汤入味

禁止无依据写：

- 非遗技艺
- 百年老店
- 每日现杀
- 有机认证
- 秘制祖传
- 全网第一

## Visual Hierarchy

卖点可使用：小型徽章、圆章、图标 + 短字、侧边标签、菜单牌结构。

不能使用数码参数卡视觉。

## Density Adaptation

信息多时做减法；信息少时增强视觉语言和语义微文案，但不编造商业事实。

后续用户可要求：增加、删除、修改、移动任意信息模块；不要因此重做 Food Hero。
